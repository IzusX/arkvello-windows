## Run and build

The current Release executable is:

`src/Arkvello.WinUI/bin/x64/Release/net10.0-windows10.0.26100.0/win-x64/Arkvello.exe`

Launch it directly, or pass `--open "C:\path\folder-or-archive"`. Ordinary startup
opens the user's home directory. This is a separate executable; the original
`build/windows-x64/7zFM.exe` remains the old Win32 prototype.

Requirements: existing MSVC x64 tools/Windows SDK used by the original build,
.NET SDK 10.0.401 (latest patch roll-forward), network access to the official
NuGet feed for the initial locked restore. The runnable build currently requires
the installed .NET 10 runtime. WinAppSDK is app-local; no installer or shell
registration is executed. SDK 10.0.26100 is a build target; Windows 10/other
Windows versions have not been validated.

```powershell
.\scripts\build-winui.ps1
# Repeat backend checks, using only disposable fixtures under build/:
$env:DOTNET_CLI_HOME = "$PWD\build\dotnet-home"
$env:NUGET_PACKAGES = "$PWD\build\nuget"
dotnet run --project tests\Arkvello.BridgeChecks -- "$PWD"
```

The build keeps the pinned codec/fixture CLI current, compiles the native bridge
directly from an explicit service source list with MSVC `/W4 /WX /MT`, restores
locked WinUI dependencies and builds Release. It does not build the old FM/GUI.
No application files outside this repository are changed. Dependencies and
build outputs remain ignored under `build/`, `bin/` and `obj/`.

## Implemented slice

- Native WinUI main window following the approved menu/navigation/commands/list/
  status order. System caption, normal resize/snap, native dialogs and controls.
- Real filesystem enumeration; editable folder/archive path; parent/back/refresh;
  errors retain the previous valid location. Explicit archive session levels
  retain parent/native item identity for nested browsing, names, sizes and
  modified times. External-editor execution is not implemented yet.
- Four stable virtualized list modes. Details has sort, resize/reorder header
  controls and horizontal overflow retaining all four initial columns. Header
  context commands provide width/order actions without a drag gesture.
  Normal WinUI pointer/Ctrl/Shift/keyboard selection; original alternative marks,
  incremental typing, all columns and complete shortcuts are not implemented yet.
- Select exact native entries, extract full paths to an explicit destination,
  or test without output. A selected directory expands to its original native
  indices. No selection targets all visible-folder entries. This does not
  implement the complete Extract option surface or all original selection
  precedence; the simplified dialog is limited to this slice.
- Real progress, native cooperative pause/resume/cancel, password request,
  overwrite choices (yes/all/no/no-all/auto-rename incoming/cancel), issue and
  cancellation results. Cancel retains possible partial output and says so.
  A result with item issues cannot be reported as clean success.
- System/light/dark preference via WinUI, native Windows Mica menu/navigation
  foundation, DWM dark caption and contrast-theme resources. No
  personalization/settings/association writes. Live changes and actual contrast
  theme acceptance still require the matrix below.

Unavailable commands are visibly disabled in the technical build. Their presence
does not count as implementation. Full Add, settings, two panels, file mutations,
shell quick actions and all remaining inventory groups are still required.

`tests/Arkvello.BridgeChecks` runs the production C# adapter against the compiled
C++ bridge and pinned `7z.dll`. The CLI only constructs disposable 7z fixtures;
the operations under test use the direct C++ route. No mock engine/progress.

Latest evidence:
`build/bridge-checks-46957d6eb5694fa4a28dd036766827a1/checks.json`,
`large-archive.json`, and `build/bridge-checks.log`.

- Unicode filename containing wildcard-like brackets, index selection and exact
  output content; unselected files absent.
- All six conflict answers, passed sizes, unchanged or replaced content and
  incoming auto-rename.
- Wrong encrypted-header password fails; a fresh attempt with correct password
  opens and extracts. Cancelling password acquisition returns E_ABORT.

  warm-environment sample, not a comparative benchmark or all-format claim.
  Cancelled archive listing is rejected.

## List measurements

The opt-in `--measure-list` mode loads 10,000 and 100,000 **synthetic** records
in each of Details/List/Small Icons/Large Icons and scrolls to the last record.
This isolates XAML realization from native archive/filesystem I/O. It writes
`build/winui-list-measure.json`; it never runs in ordinary sessions.

Initial run on this machine at actual XAML rasterization scale 1.5:
52–101 realized containers for 10,000 records and 54–101 for 100,000; the whole
process working set grew from roughly 181 to 256 MiB across the matrix. Initial
population was 332–548 ms, scroll-to-end 311–532 ms, **including an intentional
300 ms layout-settle interval per measurement**. These timings are bounded
observations, not latency percentiles or a promise for real disk I/O.

Later layout corrections change the viewport/container counts; the final repeat
must be measured separately. The initial figures above predate those changes. A fixed
row-height/finite viewport and native panel virtualization must remain intact.

## Issues found and corrected while integrating

- Supplying required OpenArchive type/exclusion vectors was necessary; omitting
  them caused an initial native access violation. They are now owned for the
  full synchronous open call; bridge checks pass. Hardware faults cannot be
  contained by the managed exception boundary.
- `AccessibilitySettings.HighContrastChanged` subscription failed with
  ERROR_NOT_FOUND on this unpackaged host and initially prevented startup.
  Theme resources/ActualThemeChanged and UISettings are used instead; system
  contrast transition still needs real acceptance testing.
- Runtime-created templates cannot resolve a window-local resource while
  parsing. The folder-icon resource moved to the application theme dictionaries.
- Default CommandBar alignment and explicitly sized list children centered the
  commands/rows. The slice now uses left-aligned commands and a stretched list
  viewport with fixed columns and horizontal overflow.
- ContentDialog lifetime is awaited when switching progress to a native prompt
  and back, avoiding concurrent dialogs on one XamlRoot. Native completion is
  awaited before closing the operation view.

milestone runs. Concrete remaining work:

   a backend with different semantics. Background/priority remains unimplemented.
3. Nested session/index identity and Agent-backed staged edit-back now have the

   conflict detection, atomic root commit/recovery, actual virtual/stream-first

4. Check native light/dark/accent transitions, actual contrast themes, text scale,
   100/125/150/200% DPI and mixed-monitor transitions, constrained dialogs and
   assistive technology. Current 150% startup is not that matrix. Do not change
   the user's display/personalization settings just to manufacture a pass.
5. Test real large filesystem/encoded archive I/O and responsiveness during work;
   add batching/lazy providers only where measurements justify it. Synthetic
   realization and a TAR list do not prove every filesystem/codec workload.
6. The dedicated native source target is implemented and checked below. Finish
   the process/priority/session ownership decision and clean-machine
   unpackaged/self-contained deployment. Bundle
   dependency notices, verify missing runtime/DLL behavior and independent shell

### Follow-up: scrolling, menu height and user scale

The user confirmed the navigation-icon/command-alignment correction, then
reported a missing vertical scrollbar, transparent horizontal track, clipped
menu labels and a need for a smaller personal UI scale.

- The list now owns horizontal and vertical scrolling. Its vertical bar stays
  on the visible viewport edge; a separate header scrolls horizontally in sync.
  The former outer horizontal ScrollViewer could place the list's vertical bar
  beyond the right edge of a narrow window.
- Native scrollbar gutters reserve space outside the item presenter; light,
  dark and contrast resources give the tracks an opaque background. The WinUI
  2.6.5 presenter template parts are an explicit SDK-upgrade check.
- The menu uses its native desired height (currently 40 DIP), instead of
  forcing a 28-DIP slot around a taller WinUI control.
- **Вид → Масштаб основного окна** offers 75/80/90/100/110/125/150% relative
  to Windows DPI scaling. It changes the main client area, including list,
  navigation, commands and menu. The system caption and popup/dialog surfaces
  keep native system sizing. 100% restores the original application scale.
  Selection persists while changing scale; resizing does not change the chosen
  percentage. The preference is stored in `%LOCALAPPDATA%\Arkvello\ui-scale.json`;
  invalid or unavailable preferences fall back to 100%. Save failures are shown.
  This is the first application preference write; it does not change Windows
  display/personalization settings.

These changes do not close the full DPI, accessibility or stage-3 gates above.

### Follow-up: native Mica foundation

The user replaced the earlier personalization-accent tint requirement with
Explorer-like wallpaper/theme material. The window now uses `MicaBackdrop`
(`Kind=Base`); transparent menu/navigation containers reveal one common backdrop.
The address field uses WinUI's neutral control fill. File content, lower command
surface, status and scrollbar gutters remain opaque. Explicit theme selection
is applied to `Window.Content` so controls and the default backdrop configuration
observe the same theme. The system owns activation, wallpaper and effect fallback;
the application does not read wallpaper files or modify transparency settings.

Microsoft describes [Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)
as an opaque material incorporating wallpaper/theme, with solid fallback for
disabled transparency, battery saving, inactive windows and unsupported systems.
The [supported WinUI integration](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops)
uses `Window.SystemBackdrop`. This implements that public material; it does not
claim access to Explorer's private, build-specific composition or exact tint.

Executed follow-up: Release build succeeded with zero warnings/errors; a real
window at the user's saved 80% scale showed continuous menu/navigation material,
then an explicit light-theme change updated controls and Mica together after
the system transition settled. Captures:
`design/winui-slice/captures/mica-dark.png` and `mica-light.png` (240 generated
files under `build/ui-layout-fixture`). This bounded check does not prove live
wallpaper changes, transparency-off, battery saver or actual contrast mode;
those continue to use native behavior and remain acceptance-matrix work.

### Nested sessions and Agent update proof

2026-11-17: `ArchiveSession` retains a parent session, exact parent native item
index and parent folder for each nested level. A child owns one decoded regular
temporary file. Returning up closes the child before deleting its owned file;
parents remain open. Archive paths are display information, never identifiers
for choosing a duplicate. Back history uses live session references; disposed
nested indices are skipped instead of being reinterpreted in a different root.
Nested refresh redraws the owned snapshot; root refresh reopens the source.

The UI opens nested archives with a double click/Enter, and returns with Up,
Backspace or Back. Up restores the selected child index in the parent folder.
Unrecognized regular files retain the earlier extraction-dialog action; no
external process/editor is launched. Default extraction output derives from the
root filesystem path, never the logical nested display path.

Two additive native calls export an exact item into a new caller-owned regular
file and stage an exact-index replacement into a new archive. They refuse to
overwrite existing output files. Directory/link/ADS items are not materialized
as regular external files by this API. The write route uses CAgent folder/proxy
index mapping and original UpdateOneFile, preserving the original item name.
`StageReplacement` builds a nested update chain into separate artifacts, checking
item names and testing every rewritten archive. It cannot overwrite the root.
Temporary cleanup removes only the known owned file and its empty directory,
without recursively deleting unexpected editor files or other contents.

Backend checks passed against the production adapter/native DLL:

- Plain replacement stays unencrypted; encrypted 7z replacement retains protected
  headers and requires a password for the changed data.
- Updating the second of two identically named TAR entries preserves the first.
- Actual-write cancellation and cancellation before writing leave the original
  readable/unchanged; existing output is never overwritten.
- TAR → ZIP → TAR browsing and staged replacement survive reopening all levels.
  The original root bytes stay unchanged; closed sessions clean their own files.
- Failed/cancelled child opens preserve the parent session. Existing extraction,
  prompt, pause/cancel, corruption and 100,000-entry listing checks also pass.

Evidence: `build/agent-bridge-checks.log` and the generated `checks.json` path
printed there. Release WinUI build passed with zero warnings/errors. Bounded
native pointer/keyboard acceptance is recorded in the follow-up below.

The first update test exposed an incompatible `Z7_DEVICE_FILE` build define;
matching native structure layouts fixed the heap corruption. The native library
now explicitly excludes old FM/GUI objects, and CAgent receives session-owned
codecs. See the revised [boundary decision](decisions/0002-working-slice-boundary.md).
The dedicated source build is recorded below. Arbitrary encrypted-format parameter fidelity,
external editing UI, root commit/recovery and stage-3 accessibility/deployment
gates remain open. Successful staging does not establish complete edit-back.

### Native navigation verification

2026-11-17: repeated real-window verification using the generated fixture
`build/bridge-checks-671f240737974985813b327086abd37d/nested.tar` in Details view,
the existing dark theme and the user's saved main-window scale.

The first pass found Enter consumed by native ListViewItem handling, selection
identities colliding across sessions, and focus falling back to the File menu
when a focused list was replaced during a key gesture. Corrections:

- Handle Enter before native item handling; resolve the focused item's container,
  including an unselected current item. Consume its release and open only after
  the key gesture finishes, so that the new surface cannot receive that release.
- Restore focus after the new list is loaded and pending layout/focus work ends.
- Scope archive row/folder identities to a session GUID plus native index/path.
  Preserve selection within a session without transferring it to unrelated
  entries with the same index in another level.
- Handle Alt+Left at the window preview boundary, matching the Back tooltip.

Final executed scenarios:

- Open the root by editable path; double-click into ZIP and its folder/TAR.
- Keyboard selection with End, then consecutive Enter gestures through ZIP,
  folder and inner TAR without opening a menu/picker. Both identically named
  inner files remain separate rows; no selection leaks into the new session.
- Up button and Backspace return to the parent folder and select leaf.tar.
- Refresh button and Ctrl+R redraw the nested folder, retaining that selection.
- Alt+Left and Back button traverse live parent history. Root Ctrl+R reopens
  the source; Up exits to its filesystem directory; Back reopens the closed root
  session without reinterpreting disposed nested indices.

Capture: `design/winui-slice/captures/nested-return-selection.jpg` (fixture only).
Release build: zero warnings/errors, `build/navigation-ui-build.log`. Final
verification executable: `build/navigation-validation/Arkvello.exe`, built with
an explicit OutputPath while an older test instance held the ordinary output.
The ordinary output directory does not contain these final keyboard corrections
until rebuilt after that older instance is closed.

This is a bounded Details-view navigation pass, not certification of every view,
original mark/current-item mode, screen reader, DPI/theme state or editor flow.
The remaining stage-3 gates above still apply.
